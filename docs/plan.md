# reMarkable 2 设备端 AI 助手 — 完整实施计划（v2：Agent 架构版）

## 1. 项目目标

在 reMarkable 2 上实现一个原生体验的 AI 能力：用户在 xochitl（原生笔记界面）里手写完内容后，通过一个手势触发 AI。AI 观察当前页面，**自行判断任务类型**（润色文字、整理待办、把潦草的示意图画工整、图文混排的笔记整理等），然后以"手写笔迹"的形式把结果写/画回设备笔记中。全程在设备上完成，无需电脑或手机中转。

**核心体验流程：**

```
手写/涂画一页 → 角落手势触发 → Agent（看图 → 决策 → 编排动作）→ 结果以笔迹/图形写入新页
```

**核心设计理念：Agent 的工具就是它的"手"。** 模型的 tool call 直接映射为设备上的注入动作（写字、画图、翻页），感知—决策—行动在一个循环里闭合。

**明确不做的事（第一版）：**

- 默认不删除/替换用户的原始笔迹（evdev 注入无法逐笔擦除；改 .rm 文件复杂度过高）。但提供可选的**原地更新模式**：注入 xochitl 自身的"清空页面"菜单操作实现 erase all，再重写本页（见 4.3/4.5，带备份与溢出续写机制）
- 不做独立全屏 app（保持用户始终在 xochitl 原生界面）
- 不依赖 toltec 或设备上的任何运行时（避免固件兼容问题）

## 2. 背景：与 xochitl 的相处之道

xochitl 是 reMarkable 官方的闭源 Qt 主程序，独占屏幕与输入，即"用户眼里的系统"。官方无 SDK，社区方案全部来自逆向，且按逆向深度呈现清晰的稳定性梯度：

| 逆向深度 | 代表项目 | 稳定性 |
|---|---|---|
| 改二进制内部（函数偏移补丁） | ddvk/remarkable-hacks | 每个固件版本都要重新逆向，最脆 |
| 钩函数（LD_PRELOAD 劫持刷新调用） | rm2fb | 固件更新常需跟进 |
| 文件格式 / 进程内存布局 | rmscene、reSnap 截帧 | 偶尔受固件影响 |
| 内核标准接口（evdev、systemd） | 本项目主体 | 内核 input ABI，最稳 |

**本项目刻意停留在最稳的一层**：只通过 evdev 与 xochitl 交互（它分不清合成事件与真笔迹），唯一向上够的是截帧（依赖 xochitl 进程内存布局），因此截帧是 M0 验证的重点，且备有降级方案。

## 3. 总体架构

单个 Go 静态二进制 `rm2-ai-daemon`，以 systemd service 常驻运行：

```
rm2-ai-daemon
├── trigger/    手势监听：读触摸屏 evdev，识别"右下角双击"类手势
├── capture/    截帧：从 xochitl 进程内存定位 framebuffer → 导出 PNG
├── agent/      Agent 循环：截图 + 工具集 → Claude API tool use loop
│   └── tools/  工具实现（见 4.3），全部落到 layout/inject
├── layout/     排版：文本 → Hershey 笔画；SVG path → 折线
├── inject/     写回：笔画坐标序列 → Wacom evdev 合成笔事件
├── ui/         xochitl UI 操作：UI 图谱（控件坐标表）+ 像素探针 + 点击状态机
└── config/     配置：API key、system prompt、手势参数、字号行距、UI 图谱（按固件版本）
```

**关键设计决策及理由：**

| 决策 | 选择 | 理由 |
|---|---|---|
| App 形态 | 常驻 daemon + 手势触发 | 用户不离开原生笔记界面 |
| AI 形态 | Agent（tool use loop） | 任务开放式：模型需自行判断任务类型并编排图文混合输出 |
| 读取手写内容 | framebuffer 截图 + vision | 绕开 .rm v6 解析和本地 OCR；vision 对手写/涂画的理解质量更好 |
| 写回方式 | evdev 笔事件注入 | 零文件格式依赖；xochitl 自动渲染保存；免重启；文字与图形同一条管线 |
| 语言/发行 | Go 静态二进制 (GOARCH=arm GOARM=7) | 交叉编译简单、TLS 自带、对固件版本免疫 |
| 字体 | Hershey 单线字体 | 天然是折线笔画，直接映射为笔迹；数据仅几十 KB |
| 图形表达 | 模型输出 SVG path → 拍平为折线 | SVG 是 LLM 最擅长的矢量表达；拍平后复用注入管线 |
| 结果位置 | 同一笔记的新一页 | 避开"删除原笔迹"难题 |

## 4. 各模块详细方案

### 4.1 trigger — 手势监听

- 直接 `open("/dev/input/eventX")` 读触摸屏（rM2 上触摸屏与 Wacom 数位笔是不同的 input device，开机后枚举确认，不要写死编号）
- 手势定义（模式即手势，权限随手势走）：
  - **新页模式**：右下角双击（区域小 + 时间窗 500ms + 两点距离阈值防误触）
  - **原地更新模式**：右下角双击 + 第二击不抬起**长按 ≥1.5s**（位移 < 阈值）——长按本身就是破坏性操作的确认，无需额外 UI。识别逻辑复用同一事件流
  - 可选二段式确认（config 开关，默认关）：原地手势触发后注入单笔画"◯"标记为 armed 态，5s 内再点角落才执行；超时注入 undo 按钮点击清除标记（单笔画=单步 undo）
- 只读事件、不 grab 设备，xochitl 照常收到触摸
- Agent 执行期间挂起手势识别（防止把注入动作或用户误触当成新触发）
- **手势触发的默认语义与翻页策略绑定**（见 4.5）：若翻页注入可靠，手势在"内容页"上触发；若降级为手动翻页，手势在"空白新页"上触发，此时 Agent 首个动作必须是 `read_page(-1)` 回看内容页
- 触发后注入一个小状态笔迹（角落沙漏）提示"处理中"；第一版可用日志代替

### 4.2 capture — 截帧

- rM2 的屏幕内容由 xochitl 进程内部渲染并私有刷新，不走 /dev/fb0；采用 reSnap / rm2fb 社区已验证的方法：从 `/proc/<xochitl_pid>/maps` 定位帧缓冲映射区域，读出原始灰度帧
- 帧格式：1404×1872，处理为 8-bit 灰度 PNG（约 50–150KB）
- **最大的固件耦合点**，M0 首先验证；降级方案见风险清单

### 4.3 agent — Agent 循环与工具集

**循环骨架**（约 30 行 Go）：调 API → 若返回 tool_use 则执行工具、回传结果 → 直到模型给出结束或达到 maxTurns。

**工具集**（daemon 侧实现，动作类工具全部落到 evdev 注入）：

| 工具 | 签名 | 说明 |
|---|---|---|
| `read_page` | (offset) → 截图 | 再看前/后一页，用于跨页上下文 |
| `write_text` | (lines, pos, size, style?) → ok + 溢出行 | 文字 → 笔画 → 注入。style={笔型,粗细,颜色}，daemon 与当前状态不符时经 UI 图谱自动切换（对模型零额外轮次）。放不下的行不注入，随 ok 返回；Agent 拿到溢出即 `new_page` 续写 |
| `draw` | (svg_paths, pos, scale, style?) → ok | SVG path → 折线 → 注入。style 同上（如标题用 Marker、图形用 Paintbrush） |
| `new_page` | () → ok | 翻到新的空白页 |
| `erase_page` | () → ok | 注入 xochitl"清空页面"菜单操作整页清空（非逐笔擦除）。**权限门控：仅"原地手势"触发的会话才把此工具注册给模型**——普通会话的工具表里没有它，模型无入口可误用。执行前 daemon 自动备份笔记本 .rm 文件，用户亦可 undo 撤销 |

**工具分层原则**：UI 操作（换笔/undo/开关工具栏）是 daemon 原语（4.6 图谱驱动），**不作为独立 Agent 工具暴露**——模型通过动作工具的 style 参数声明意图，daemon 内部编排点击路径。唯一例外是 erase_page（破坏性，需独立门控）。undo 第一版仅供 daemon 内部错误恢复使用。**会话礼仪**：会话开始时从 .content `LastPen` 读取用户当前笔型，结束时恢复——用户不应发现自己的笔被换过。

**工程边界（三条硬规则）：**

1. **maxTurns = 8**。合理循环是"看图 →（可能回看上一页）→ 2–4 个动作"，正常 4–6 轮；上限只是打转保险，真正防打转靠 prompt 约束与工具幂等，因此留足余量（手动翻页降级形态每次固定多一轮 `read_page`）。超出即截断并注入错误提示。
2. **动作工具同步阻塞、结果只回 "ok"**。注入一页字需几十秒，不回传截图让模型确认（延迟翻倍），相信注入的确定性。
3. **一次规划、批量执行**。system prompt 明确告知："你在 e-ink 手写板上通过笔迹输出，动作昂贵且不可撤销，先在思考中确定完整方案再执行"——防止模型像操作屏幕 UI 那样试探性小步操作。

**System prompt 要点**：设备与画布尺寸、可用区域、行宽字符预算、任务判断准则（何时润色/总结/重绘图形）、输出语言约定。模板可配置多套。

**API 客户端**：多供应商可配置——`provider = anthropic | openai`（openai 段兼容自建 vLLM/Ollama 等 self-hosted 端点，config 含 base_url/model/api_key）。内部抽象统一的 agent 接口（消息 + 工具定义 + 工具结果），两套 tool use 协议各写一个薄适配器。**硬性要求：模型必须支持 vision**（看图是感知的唯一通道），self-hosted 需选多模态模型（如 Qwen-VL 系）。单轮超时 60s；失败注入"×"笔迹提示。API key 存 `/home/root/.config/rm2-ai/config.toml`。注意：rM2 上一切皆 root，文件权限不构成保护，真实风险是设备丢失与 USB web 接口暴露——文档中如实说明。

### 4.4 layout — 文本与图形转笔画

- **文字路径（英文）**：Hershey 字体数据 go:embed 打包；排版参数（字号默认 40–50px 高、行距 1.5、边距）；输出 `[]Stroke`（点列 + 抬落笔标记）。✅ 已在 m0 验证（futural.jhf，62 字符约 11s，比例间距/下伸部正常；行距需 ≥1.8 倍大写高度避免下伸部相碰）
- **文字路径（中文）**：SVG 笔画数据路线 ✅ 已验证——KanjiVG 数据直接可用且含笔顺，但为日文汉字集（部分简体字缺）；正式版换 **makemeahanzi / hanzi-writer-data**（9000+ 简体字，同格式）。中文与图形共用 SVG path 解析器，无需独立字体引擎
- **图形路径**：解析模型输出的 SVG path（M/L/H/V/C/S/Q/T/Z + A 降级为直线），贝塞尔按固定细分拍平为折线，输出同样的 `[]Stroke` —— 与文字共用后续管线。✅ 已验证（17 笔画手绘图注入正常，e-ink 上看不出折线感）
- 坐标系转换 ✅ 已标定：screen_x = wacom_y×1404/15725；screen_y = (1−wacom_x/20966)×1872

### 4.5 inject — evdev 笔迹注入

- 向 Wacom 笔 input device 写合成事件序列：`BTN_TOOL_PEN=1` → 移至起点 → `BTN_TOUCH=1` + 压力 → 沿点列移动（每点 SYN_REPORT）→ 抬笔
- 点间隔 3–8ms：太快 xochitl 丢点致笔画断裂，太慢整页耗时过长；做成配置项实测调优（✅ 实测 4–5ms 无断笔）
- **压力包络 = 手写感（实测结论）**：恒定压力注入的笔迹是均匀细线，"机器描线感"明显；加"起笔快速加压(10%)→中段满压→末段 30% 渐提"的包络后，xochitl 压感笔刷渲染出粗细变化，观感接近真人手写。底压建议 3300–3600（上限 4095）。已知改进方向：楷书横/竖收笔应为**顿**而非提，KanjiVG 每笔带 `kvg:type` 类型标注，可按笔画类型（横/竖/撇/捺）选择包络；包络参数进 config 作为"字迹风格"
- `new_page` 实现：优先注入 xochitl 翻页/新建页的触摸手势；不稳定则降级为"用户手动翻到空白页后触发"
- `erase_page` 实现：注入触摸序列（开菜单 → 点"清空页面"）。注意这是 **UI 布局耦合**（固件升级可能挪按钮位置），坐标进 config；更稳的做法是点击前截帧确认菜单已弹出再点。安全网三层：擦除前截图留档 + .rm 文件字节级备份（纯复制不解析）+ xochitl undo 栈保留（清空=1 步可撤销）
- **整页预算与溢出**：排版是确定性的，注入前即可精确判断内容是否放得下（可用高度 = 1872 − 上下边距）。溢出部分不注入、返回给 Agent 决策 new_page 续写。system prompt 附每页预算参考（英文 50px 约 550 字符/页，中文 100px 约 200 字/页）
- **降级的连锁影响**：手动翻页意味着手势发生在空白页上，截到的首帧是空白页——Agent 必须以 `read_page(-1)` 开局才能拿到内容。这改变 system prompt（明确告知"你在空白页上，内容在上一页"）并使每次任务固定多一轮，翻页策略因此不是交互细节，在 M0 与截帧、注入一同验证

### 4.6 ui — UI 图谱与像素探针

xochitl 的 UI 操作（换工具/撤销/加页/清空页）统一走"图谱 + 探针 + 状态机"，不做每步全帧截图：

- **UI 图谱**：config.toml 中按固件版本分段（顶层键=版本号，启动时读 update.conf 选段，无匹配段则拒绝 UI 动作并提示标定，绝不盲打）。每段三层结构：
  - `probes`：命名状态 → 像素区域 + 期望值（如 toolbar_open、pen_selected、add_page_btn）
  - `controls`：控件 → 点击点 + requires（前置探针）+ verify（后置探针）
  - `features`：功能 → 控件序列（多级菜单即路径；`?` 后缀=条件步，状态已满足则跳过）
  - 坐标一律存**屏幕空间**，触摸 Y 翻转只在注入代码一处完成（图谱可读可校对）
  - **完整图谱已实测并存档于 `docs/ui-map-3.11.2.5.toml`**：工具栏全按钮、笔选项面板（8 种笔/3 档粗细/5 色，每种笔独立记忆粗细）、橡皮面板（含 **Erase all 按钮 (290,794)**——erase_page 无需二级菜单）。关键时序：普通点按 ≥60ms，打开选项面板需 ~200ms 长按。erase_page 全链路盲打已验证（终态探针校验通过）
  - 远期：新固件图谱由视觉模型自举——标定时截全帧让模型标注图标坐标，自动生成新版本段（UI 耦合风险自愈）
- **像素探针**：状态判断不截全帧——按坐标算 framebuffer 偏移，dd 读几百字节即可（毫秒级）。用途：工具栏是否展开、当前选中工具（选中态图标反色黑底）、瞬态按钮是否出现
- **状态机**：动作 = 前置探针 → 盲打 tap 路径 → 后置探针验证迁移；**探针失败必须降级全帧截图重定位**（防意外弹窗时盲点击）
- **点击间缓冲 = 探针轮询而非固定 sleep**：每次 tap 后以 ~150ms 间隔轮询后置探针，探到期望状态立即执行下一步（fb 内存先于墨水屏就绪，通常 200–400ms），超时 2s 降级截图。保留 150ms 硬下限防相邻快击被识别为双击/触发内部竞争（幽灵页事件疑为快速连击的状态竞争所致）
- 已实战验证：程序化点击撤销按钮成功移除笔画；工具切换同路径可达

### 4.7 部署与运维

- `Makefile`：`make build`（交叉编译）→ `make deploy`（scp 到 10.11.99.1）→ `make install`（systemd unit + enable）
- systemd unit：`After=home.mount xochitl.service`，`Restart=on-failure`
- 日志走 journald；`--debug` 前台模式便于开发
- 固件升级可能清掉修改：文档说明升级后重跑 `make install`

- 剩余工作：重构进 `layout/`+`inject/`；自动换行/边距排版；`write_text`/`draw` 工具签名对齐 4.3 节
- 验收（量化）：命令行输入 200 字符英文文本，注入无断笔、无丢点畸变，总耗时 < 60s，行距边距符合配置
- **教训（写进 Agent 设计）**：m0 期间发生过"未先截帧就注入、实际页面已被用户翻走"——所幸落在空白页。正式 Agent 每次动作前必须 read_page 确认页面状态，此约束进 system prompt 与工具实现双层兜底

**M2 — 读取链路 + 单轮调用（2–3 天）**
- capture + agent（maxTurns=1、仅 write_text，等价单次调用的退化形态）
- 验收：命令行触发后，手写内容被识别、润色并写回

**M3 — 完整 Agent + 手势（4–6 天）**
- trigger + `draw`（SVG 拍平）+ `read_page` + `new_page` + 状态提示 + systemd 部署
- 验收 A：纯设备操作完成"手写 → 手势 → 润色文字写入新页"
- 验收 B：手绘一个潦草流程图 → 手势 → Agent 在新页画出工整版本

**M4 — 打磨（持续）**
- 多 prompt 模板、注入速度调优、断网/错误处理、中文写回字体（makemeahanzi + 按笔画类型压力包络）、配置文档
- **原地更新模式**：erase_page（菜单 tap 序列先做 m0 式验证）+ write_text 溢出续写 + .rm 备份机制；触发=双击+长按手势（即确认），二段式 armed 确认为 config 可选

## 6. 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| framebuffer 定位对当前固件失效 | 高 | M0 首先验证（含固件版本记录）。注意："解析 .rm 文件离线渲染"不是降级而是换项目——rmscene 是 Python 实现、v6 格式仍在演进，等于在 Go 里重写解析器+渲染器，M2 推倒重来。故 M0 若发现失效，优先考虑锁死固件版本而非切换方案 |
| evdev 注入丢点/笔画畸变 | 中 | 调点间隔与插值密度；M0 验证 |
| 模型 SVG 输出质量不稳（自交、比例失调） | 中 | prompt 中给画布网格约定与示例；layout 层做边界裁剪与尺寸归一化 |
| Agent 循环打转 / 动作编排混乱 | 中 | prompt 约束（一次规划批量执行）+ 动作工具幂等为主，maxTurns=8 仅作打转保险 |
| 翻页手势注入不可靠 | 中 | 降级为手动翻页，不阻塞主流程 |
| erase_page 菜单坐标随固件变化 | 低 | UI 图谱按固件版本存档；点击前后像素探针验证，失败降级全帧截图（见 4.6） |
| xochitl 运行时状态异常导致注入静默失败 | 中 | 实测为**间歇性**（同类空白页有的三连拒、有的一次通过，根因在 xochitl 内部不可见）。对策三层：关键写入后像素探针校验"确实有墨" → 无墨则富 hover 序列重试一次 → 仍无墨报错并注入"×"提示，绝不静默继续 |
| 中文写回缺单线字体 | ~~中~~ 低 | ✅ KanjiVG 路线实测通（含笔顺、书法曲线）；正式版用 makemeahanzi 补简体覆盖，复用 SVG path 管线，成本远低于原估 +1 周 |
| 固件升级破坏部署 | 低 | 静态二进制 + 一条命令重装 |
| Agent 多轮延迟 | 低 | e-ink 用户等待容忍度高；状态笔迹提示；动作工具不回传截图 |

## 7. 已决策 / 仍开放的问题

**已决策：**
- AI 形态：Agent（tool use loop），因任务开放式（文字 + 图形）✔
- 图形能力：第一版即包含 `draw` 工具（SVG path 路线）✔
- API 供应商：多供应商（anthropic / openai 兼容 / self-hosted），统一 agent 接口 + 双协议薄适配器；模型硬性要求支持 vision ✔（2026-07-17 修订，替代此前"只接 Anthropic"的决策）
- maxTurns = 8：上限是打转保险而非流程约束，防打转靠 prompt + 幂等 ✔

**M0 后已关闭：**
- ~~翻页策略~~：翻页注入实测 10/10 可靠，走全自动路线，无需降级形态 ✔
- ~~固件锁定~~：截帧在 3.11.2.5 上直接可用，无需打补丁；像素格式与老文档不同（u16 灰度 0–30），已实测记录 ✔
- ~~原地更新的触发与确认~~：手势即确认（双击=新页，双击+长按 1.5s=原地），erase_page 工具仅在原地手势会话中注册（权限门控）；二段式 armed 确认作 config 可选项，默认关 ✔

**仍开放：**
1. **写回语言**：第一版只支持英文输出，还是必须中文？（KanjiVG/makemeahanzi 路线已验证，成本已大幅下降）
2. **模板切换**：原地/新页的决策已确立"手势=模式+工具集+prompt"范式，模板切换大概率沿用（新手势=新模板）；剩余问题仅是手势词汇表设计（哪些角落/组合留给哪些模板）
3. **new_page 精确化**：最后一页向前滑动会连续建页（过触发），需 record 真人操作后确定最小可靠事件序列。首笔问题已降级：注入首笔可建档（间歇故障由"验墨→hover 重试→报错"三层防御兜住）
